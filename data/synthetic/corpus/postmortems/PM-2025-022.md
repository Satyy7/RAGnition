# PM-2025-022: Intermittent timeouts across services on Black Friday  
**Date:** 2025-11-28 | **Severity:** SEV2 | **Service:** cluster-dns  

## Summary  
During the Black Friday traffic peak, a surge in DNS queries caused CoreDNS pods to become CPU‑throttled. The throttling led to dropped DNS queries, resulting in intermittent connection and lookup timeouts for several downstream services. Scaling CoreDNS and removing CPU limits restored normal operation after 55 minutes.

## Impact  
- 2‑4 % of requests across many services failed with connection or lookup timeouts.  
- Affected services included checkout‑api, payments‑api, search‑api, inventory‑api, and order‑worker.  

## Detection  
Error‑rate alerts fired in five services within minutes of each other (checkout‑api, payments‑api, search‑api, inventory‑api, order‑worker). The alerts indicated a sudden increase in DNS‑related errors.

## Timeline  
- **18:00** – Black Friday traffic peak begins (≈ 9× baseline).  
- **18:06** – Alerts triggered in checkout‑api, payments‑api, search‑api, inventory‑api, order‑worker.  
- **18:20** – Common error “lookup … i/o timeout” identified across services.  
- **18:55** – CoreDNS scaled from 3 to 8 replicas and CPU limits removed; services recovered.  

## Root cause  
CoreDNS pods were CPU‑throttled at peak load. The default `ndots:5` setting caused each lookup of an external or partially qualified name to generate multiple DNS queries, amplifying the load on CoreDNS. The saturated CoreDNS instances dropped queries, leading clients to see “i/o timeout” errors.

## Trigger  
Black Friday peak traffic, approximately nine times the normal baseline, generated a DNS query volume that exceeded the capacity of the statically sized CoreDNS deployment.

## Resolution  
- Scaled CoreDNS from 3 to 8 replicas.  
- Removed CPU limits on CoreDNS pods, allowing them to use available CPU resources.  

## Contributing factors  
- Fixed CoreDNS replica count not tied to cluster size or traffic patterns.  
- `ndots:5` default amplified DNS queries for external or partially qualified names.  

## Action items  
- Run `cluster-proportional-autoscaler` for CoreDNS with a minimum of 6 replicas (completed).  
- Use fully‑qualified domain names with a trailing dot for hot external hosts (partly done).  

## Lessons learned  
- Static replica counts for critical infrastructure services can become a bottleneck under traffic spikes; autoscaling should be employed.  
- DNS configuration defaults such as `ndots` can unintentionally increase query load and should be reviewed for high‑traffic environments.  
- Monitoring for CPU throttling on CoreDNS pods provides early indication of DNS capacity issues.  
- Using fully‑qualified domain names reduces the number of queries generated by the resolver, mitigating load during peak periods.
