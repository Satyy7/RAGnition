# PM-2025-024: Product pages slow after variant attributes release  
**Date:** 2025-12-03 **Severity:** SEV3 **Service:** catalog‑api  

## Summary  
A release (7.9) introduced a new `color_code` column used in product variant queries. Because the column lacked an index, queries performed full sequential scans of the 35 M‑row `product_variant` table, causing a sharp increase in product page latency. The issue was detected by the StorefrontLatencyHigh alert, investigated, and resolved by creating a concurrent index on `color_code`. Latency returned to normal within 95 minutes.

## Impact  
- Product page 95th‑percentile latency increased from 0.4 s to 3.8 s.  
- The degradation persisted for approximately 95 minutes, affecting all storefront users during that window.

## Detection  
The StorefrontLatencyHigh alert fired at 09:20, indicating elevated latency on the storefront. Subsequent inspection of `pg_stat_statements` at 10:10 revealed unexpected sequential scans on `product_variant`.

## Timeline  
- **09:00** – Release 7.9 deployed.  
- **09:20** – StorefrontLatencyHigh alert triggered.  
- **10:10** – `pg_stat_statements` showed sequential scans on `product_variant`.  
- **10:35** – Index `CONCURRENTLY` created on `color_code`; latency began to recover.  

## Root cause  
The new `color_code` column was added to query filters without a supporting index. Each query therefore performed a full table scan of the 35 M‑row `product_variant` table.

## Trigger  
Release 7.9 introduced queries that filtered `product_variant` by the newly added `color_code` column.

## Resolution  
Created a concurrent index on `product_variant(color_code)`. The index eliminated the sequential scans, and latency returned to baseline levels.

## Contributing factors  
- Migration review did not include `EXPLAIN` plans for the new hot queries, so the missing index was not identified before deployment.

## Action items  
- **Migration checklist** – attach `EXPLAIN` for every hot query touching changed indexes or columns (done).

## Lessons learned  
- Adding columns that become part of query predicates requires an accompanying index review.  
- Migration checklists should mandate performance plan verification (`EXPLAIN`) for any query that could become hot after a change.  
- Early visibility into query execution (e.g., via `pg_stat_statements`) is critical for rapid detection of unexpected full scans.  
- Deploying schema changes without index support can have immediate, large‑scale latency impact on high‑traffic services.
